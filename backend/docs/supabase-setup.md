# Supabase Setup Guide

Cryptalk uses a **single Supabase project** for everything: PostgreSQL database, file storage,
and (client-side) auth keys. No other database provider is needed.

---

## 1. Create the Project

1. Go to [supabase.com](https://supabase.com) → **New project**.
2. Choose a name (e.g. `cryptalk`), a strong database password, and the region closest to your
   Render service (e.g. Oregon / `us-west` for Render's default region).
3. Wait for provisioning (~2 minutes). Save the database password — you'll need it for `DATABASE_URL`.

> The free tier includes 500 MB database + 1 GB storage — enough for Cryptalk's defaults
> (`STORAGE_QUOTA_BYTES` ≈ 950 MB per user quota pool).

---

## 2. Database — `DATABASE_URL` (required)

The backend connects to Supabase PostgreSQL via one environment variable:

| Variable | Where to get it |
|----------|-----------------|
| `DATABASE_URL` | Supabase Dashboard → **Settings → Database → Connection string → URI** |

Format:

```
postgresql://postgres:YOUR_PASSWORD@db.YOUR_PROJECT.supabase.co:5432/postgres
```

Notes:

- Replace `[YOUR-PASSWORD]` in the URI with the password from step 1.
- Any `postgres://` or `postgresql://` URL is automatically converted to
  `postgresql+asyncpg://` internally (`backend/app/core/config.py` → `database_url` property).
- The app **refuses to boot** if `DATABASE_URL` is unset (`config.py` → `validate()`).
- Use the direct connection (port `5432`) — SQLAlchemy/asyncpg handles pooling.

### Run migrations

```bash
cd backend
alembic upgrade head
```

Migrations run automatically on first boot if the schema is empty; run them manually when
deploying schema changes.

### Schema & RLS

The full PostgreSQL schema and Row Level Security policies live in
[`supabase/README.md`](../../supabase/README.md). Apply them via the SQL editor in the
Supabase dashboard if you manage the schema there instead of Alembic.

## 3. File Storage — `SUPABASE_URL` + `SUPABASE_KEY` (required)

Used for encrypted file uploads (images, documents, voice notes).

| Variable | Where to get it |
|----------|-----------------|
| `SUPABASE_URL` | Dashboard → **Settings → API → Project URL** |
| `SUPABASE_KEY` | Dashboard → **Settings → API → `service_role` key** |
| `SUPABASE_BUCKET` | Optional — bucket name (default `cryptalk`) |

Setup:

1. Dashboard → **Storage → New bucket** → name it `cryptalk`.
2. Keep the bucket **private** — files are served through signed URLs generated by the backend.
3. Copy the `service_role` key into `SUPABASE_KEY`.

> ⚠️ The `service_role` key bypasses RLS. It must only ever be set server-side (Render env /
> local `.env`). Frontend and mobile use the public `anon` key instead.

Files are ephemeral by design: uploaded blobs are deleted automatically after delivery
(`FILE_RETENTION_HOURS`, default 1 hour).

---

## 4. Environment Variables Summary

```bash
# Database (required)
DATABASE_URL=postgresql://postgres:PASSWORD@db.YOUR_PROJECT.supabase.co:5432/postgres

# Storage (required)
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_KEY=eyJhbGciOi...          # service_role key — server-side only
SUPABASE_BUCKET=cryptalk            # optional, default "cryptalk"
```

Full reference: [`ENV_GUIDE.md`](../../ENV_GUIDE.md).

---

## 5. Verify

1. Backend boots without `RuntimeError` about `DATABASE_URL`.
2. Register a user → row appears in Supabase → **Table Editor**.
3. Upload a file in a chat → object appears under Storage → `cryptalk`.
4. Deliver/read the message → blob is removed (ephemeral cleanup).
